Security

Verify the download. Then read what the site promises not to do.

The highest-value security step for any distributed binary is checking that the file you received is the file the release published — by comparing the SHA-256 checksum, and by downloading only from the links this site renders. Everything else on this page is the project's own housekeeping.

Verify what you downloaded

Compare the SHA-256

  1. Download only through a link shown on the downloads page or release centre, which are rendered from the release data — never from a link in an email, chat, or a conversation from anyone.
  2. Compute the hash of the file on your device. On Windows with PowerShell: Get-FileHash file.ipa -Algorithm SHA256; on macOS and most Linux: shasum -a 256 file.ipa.
  3. Compare it, character for character, with the value shown on the downloads page. It is recomputed from the exact released bytes; a mismatch means the file is not the released artifact, and nothing on this site becomes trustworthy at that point.

The checksum proves integrity — the file is the one the release published. It does not prove safety or make the app more reviewable. Those remain Apple-review and personal-judgement questions.

Understand what signing means here

PwEevee publishes unsigned builds deliberately. The certificate your device will trust must be yours, and it is the signing tool that holds it — on your device, protected by Apple, never sent anywhere by the website. The documented boundary: the browser-side validator reads files you select in the tab and reports what they contain, and no re-signing or re-signing support is served remotely.

The site never silently rewrites a build's bundle identifier or entitlements to let signing pass — that would defeat the provisioning model, and it is stated as a non-feature, not a bug.

The site's own security posture, in plain language

CSP and isolation

The website ships a strict Content Security Policy. Scripts are same-origin only — 'self' — with no unsafe-inline, so an injected attribute cannot execute in your tab. Images are likewise same-origin; third-party fonts, CDNs and analytics never appear in the request list. The theme controller, the installer validator and the site's interactivity are three JavaScript files checked into the repository, so everything that downloads is reviewable and the automated suite makes third-party script or hostnames a build-time failure.

Generated content, no parsing shortcuts

Release notes and any upstream-described content arrive pre-generated: the renderer builds the final pages ahead of time from the return values of the GitHub API, and escaped, structured rendering is applied at render time. This means a host that can pollute a release description cannot steer the page and cannot inject executable markup into your tab.

The credentials boundary

The installer page does not have an upload endpoint — there is nothing to upload to. Any file you select is read by the page's own script and never sent anywhere; that property is enforced by the absence of endpoints, not by promises in prose. The automatic suite re-checks on each build that the installer script contains no request-primitives (fetch, XMLHttpRequest, WebSocket, sendBeacon), no durable-storage writes, and no third-party host references.

Update pipeline

A server-side update script reads the GitHub API on a schedule and writes snapshot files. Where a token is used at all, it is stored as an environment secrets in the repository's configuration, shipped nowhere, rendered nowhere, logged nowhere: no token value appears in any generated page or in any repository file. Every download URL the site will render is checked against an allowlist of safe-URL rules before it becomes a link you can click.

What this site never runs

Nothing in the browser code performs code signing, signature validation or Apple provisioning — and the automated suite keeps it that way. A page that promised those things and then silently implemented something weaker would be worse than a page that honestly states it does validation only. The architecture documents say where each capability lives, and why.

Report a security concern

If you have found something that puts credentials, downloads or the website itself at risk, do not file a public issue with the details — open an issue, say that the matter is sensitive, and submit the technical detail after the maintainer asks for it on a private channel. This keeps the report timestamped without publishing attack surface.
