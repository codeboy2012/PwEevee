Install guide

Download, verify, sign, install.

PwEevee ships as an unsigned IPA published through its own GitHub release. The three steps below — download the release, verify its SHA-256, sign it with your own certificate — are the same for every signing tool, because the file is the same file. Nothing is claimed as installed-and-tested unless it was tested; compatibility notes on this page are labelled by where they came from.

Step 1 · Download

Get the release file from GitHub.

The current release, its file size and its checksum are read straight from the GitHub release the file is published in. If the release data cannot be read right now, the download and the checksum are hidden rather than guessed.

Step 2 · Verify

Check the SHA-256 before you sign.

The site shows the checksum that GitHub publishes with the release asset (full value on the panel above, first 16 characters on asset lists). Compute the file’s checksum locally and compare — if they differ, you do not have the release file.

How to compute it

  • macOS / Linux — shasum -a 256 FILE.ipa
  • Windows (PowerShell) — Get-FileHash -Algorithm SHA256 FILE.ipa
  • Windows (cmd) — certutil -hashfile FILE.ipa SHA256

Compare against the value shown on this page or on the GitHub release itself. Both are read from the same release data; nothing here invents a checksum.

Why it matters

It confirms the file you downloaded is the file the release published — a real integrity check, not proof the build is safe to run against Apple’s policies. You are still side-loading Spotify software that the App Store does not distribute; treat any third-party IPA with the usual caution and use your own signing identity.

Step 2½ · Local workshop

Validate an IPA, a profile and a certificate — in your browser.

Pick up to three files below: the IPA you downloaded, your .mobileprovision and (optionally) your .p12. Everything is parsed inside this tab by code that belongs to this page — the workshop performs no network requests of any kind, and the site's test suite proves it.

Where your files go: nowhere.

  • Nothing is uploaded. The validation engine includes no networking code at all — no HTTP, no WebSocket, no analytics, no third-party scripts. Your browser's dev-tools Network tab stays empty on this page, and that is asserted by the site's tests.
  • Nothing is stored. No localStorage, no IndexedDB, no cookies — the file references live in tab memory only and are dropped when you clear the session or close the tab.
  • Memory clearing is not deletion. We will not claim browser memory is forensically erased. The honest guarantee is different and stronger: the bytes never left your device, so there is no server-side copy to worry about.
  • Signing is not attempted in the tab. Reproducing Apple's code-signing pipeline (Mach-O signature revision, entitlements, profile embedding) reliably inside a web tab is not supported by any browser engine; instead of pretending to sign, this page validates what it can read truthfully, explains what it cannot, and leaves the actual signing to the on-device tool you choose — which keeps the credentials local too. Supported signers are listed in the section below.

1 The IPA

Reads the ZIP structure, the main app's bundle ID and version, its embedded frameworks, dylibs and extension bundles, and computes the SHA-256 of exactly the bytes you picked so you can compare against the release checksum above.

2 Provisioning profile

Reads team, App ID wildcard, expiration, device binding, App Groups and push entitlements directly out of the CMS envelope, and cross-checks the profile's bundle ID against the IPA you analyzed. A mismatch is called unsupported, not “probably fine”.

no file chosen

3 Certificate file (.p12) — optional, structural only

Confirms the container is a real PKCS#12 envelope before you hand it to a signer. The certificate and key inside an Apple-exported .p12 are PBE-encrypted; this page deliberately does not decrypt them, so no plaintext private key ever exists in the tab. Expiry, identity and key/pair correspondence are determined by the signer after you enter the password on your own device.

The self-test builds throwaway IPA, profile and PKCS#12 fixtures in memory — including ones that must fail (an expired profile, a bundle-ID mismatch, non-profile junk) — and pushes them through the exact same code paths the file pickers use. It runs it before you trust the engine with a real certificate file. It also never touches the network.

FAQ

Questions people asked.

Does my certificate or password leave my device?

No. The engine performs zero network I/O — not HTTP to this site, not telemetry, nothing. What is received by the browser stays in the browser. Password entry isn't even taken here: the .p12 is never decrypted at all.

Why does this page not just sign the IPA for me?

Because a browser cannot honestly recreate Apple's pipeline — code signature blob formats, Mach-O revision, provisioning-profile embedding, resource sealing — and a fake success would be worse than an honest gap. Any claim the page could not back up technologically is a hard “not claimable” row, and the signer tool of your choice does it properly.

Where does the signed IPA go once the signer has it?

Wherever the signer's own flow puts it: AltStore installs the file, SideStore can re-sign and install it on-device, Xcode can push it to a connected device. Nothing on this page can observe those outcomes, so nothing here claims them as done.

Do you host my signed build anywhere?

There is no hosting flow on this page at all — no upload exists to turn into a hosted build. If you want to hand an IPA to another person, do it over your own channel; this site does not host user-signed artifacts.

What about Android?

PwEevee is an iOS IPA — bundled. Reading this on Android? The workshop still runs (its checks are browser-level), but there is no build of this self-hosted app for Android

I have a free Apple ID. Does that work?

Yes: free-provisioning (personal team) profiles are the common path, and the workshop reads them fully. Note the 7-day refresh and 3-app limit, and that the profile's bundle ID must equal the IPA's — the workshop detects a mismatch for you before signing.

Sign & install tools

Which tool signs it for you.

Pick one tool and follow its docs for signing an existing IPA. These tools are third-party applications with their own requirements (accounts, certificates, refresh scheduling); their installation steps live in their documentation, and PwEevee does not mirror or certify any of them.

AltStore Classic

Uses your Apple ID’s free-provisioning certificate. Installs from a computer running the AltServer companion; on a free Apple account apps are limited to three and must be refreshed inside 7 days.

Source: altstore.io

SideStore

AltStore-style sideloading that can refresh on-device. Import the signed IPA into the SideStore app to install it, or install over the network from the paired computer by opting in.

Source: sidestore.io

Other known-good signers

  • Feather — on-device signing and install
  • Sideloadly — computer-based signing with a free or paid certificate
  • AltStore on-device — same app, installed copy of AltServer, no Mac required

Any signer that accepts a plain IPA works; what changes between tools is how the certificate is obtained and kept alive.

The app inside a PwEevee IPA is Spotify; the spoti.pw and EeveeSpotify tweaks are already inside the build — there is nothing else to install afterwards. Logo and Apple-ID DataStream setup belong in the signing tool you choose.

Installing from the SideloadLabs AltSource

AltStore and SideStore can also talk to an installed AltStore-format source: a JSON manifest that lists ready-made IPA variants so the app can fetch them in-app. These independent builds are published by SideloadLabs, not by PwEevee; PwEevee reads that manifest and links it, and does not mirror it.

What to try, in order

Troubleshooting.

The installer refuses the IPA

  • verify the SHA-256 first — a truncated download is the most common cause
  • your free Apple account already signs three apps (free-provisioning limit)
  • the IPA targets a newer Spotify than your certificate or the signer allows

Install works, app then crashes or the tweak is missing

  • check whether the signer ships its injection mechanism needed by the tweaked build
  • re-sign freshly: reusing a stale provisioning profile is a known source of launch crashes
  • report it on GitHub issues with your exact iOS version, signing tool and PwEevee version

Known limits are stated, not papered over: PwEevee builds are unsigned and no physical-device install is tested by this site’s maintainer in every environment. Where a compatibility claim has not been verified, this site says so on the project page rather than claiming success.

Platform check. PwEevee is currently available for iOS only.
