Privacy

What this website does with your data: almost nothing, on purpose.

This is a static website. There is no visitor-facing server code, no analytics, no cookies, no account system and nothing to sign in to. Everything on it is a page the site's renderer produced in advance. This page states what remains, so there is no need to take a promise on faith.

What stays entirely in your browser

Files you select in the installer

Any file you hand to the install guide's validator — an IPA, a provisioning profile, a certificate container — is read directly by your browser from your disk. Nothing is uploaded, ever, to any endpoint: correctly stated, no upload endpoint exists. The site is a set of static files and the validator is a script that runs in your tab.

In-page credentials never stay anywhere durable: the site stores nothing in localStorage, sessionStorage, IndexedDB or cookies except one non-sensitive theme preference (below). The technically-correct cleanup step is closing the tab; clearing in-page references is offered, but no software can promise erasure from physical memory.

One display preference

The only value this website will ever put in storage is your colour-theme choice — light or dark — kept as a single non-sensitive preference in localStorage under the key pweevee-theme.

No sensitive input can be stored there, and the key contains nothing that identifies you, your device, or anything you have opened. Clearing browser settings or site data removes it; without it the site simply follows your operating system's theme.

What leaves your browser

The requests a visit makes

Visiting this site makes ordinary HTTP requests to its own origin for the pages, the stylesheet, the script, and the icons. That is the complete list. The pieces at the edges of what this project controls:

  • No analytics script is loaded — no third-party script appears on any page, enforced by a strict Content Security Policy whose script-src and img-src are same-origin only. There is no tracking pixel anywhere in the page source.
  • No cookies are set and no external requests are made from a normal page view: there is no CDN, no font host and no client-side third party in the request list.
  • Release statistics come to the visitor pre-fetched and cached: a server-side update script (run by the project, not by your browser) reads the GitHub API on a schedule and writes a snapshot file. The page you receive contains the snapshot. Your browser never calls GitHub directly during a visit and cannot, for want of any route that would allow it.

What the hosting provider sees

The site is hosted on SkyTweak infrastructure. Any hosting provider sees its own server-level access records (standard web-server metadata: IP address, requested URL, user agent, timestamp). Those are the provider's logs, not an application the project operates. The project has no application-level logging of your visit, and no mechanism to connect a visit to an identity — and it does not claim control over anything at the infrastructure layer it does not operate.

Nothing on this page promises that any provider, CDN operator or upstream service does or does not log what it receives. That governance belongs to whoever operates the infrastructure — and this page tells you as much rather than implying otherwise.

When you contact the project

Reaching the project goes through GitHub's issue tracker (support) or the channels listed on the contact page. Any issue you file is public on GitHub under GitHub's own account and data-handling rules. The project has no contact database, no ticket system, no cross-referencing of who said what, and never asks for private keys or certificate passwords. If you volunteer details in an issue, they stay with that issue.

Fine print for how this page is written

Every claim above describes what the current v3 website build actually does, verified by the site's own automated tests, which make the CSP rules, the absence of analytics- and tracking-shaped request URLs, and the script inventory part of the build pass itself. The this is a one-person project, the claims on this page are reviewed when the site changes, and if a future build ever adds anything a server might write or accept, this page gets rewritten first — before the feature ships.
