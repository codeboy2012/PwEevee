## About

**PwEevee** is an independent project focused on integrating, packaging, testing, and distributing modified Spotify iOS builds.

PwEevee does not attempt to recreate the upstream projects it uses. Instead, it combines upstream components with PwEevee's own integration, build, packaging, documentation, and distribution work.

The project currently works with:

- **EeveeSpotify**
- **SpoTi.pw**
- Spotify iOS builds
- Supporting dependencies and components
- IPA integration and packaging
- Compatibility and validation workflows
- Release and distribution infrastructure

The goal is to make the resulting builds easier to understand, install, and distribute while maintaining clear attribution to the original projects.

> **PwEevee is an independent project and is not affiliated with Spotify or Apple.**

## Update channels

PwEevee's in-app update checker (Mod Settings → Mod → Updates) offers three release
channels. The build listens to one at a time and compares itself only against the
releases that channel hands out:

| Channel | What it gets | Risk |
|---|---|---|
| **Stable** (default) | Fully published releases intended for general use | The most tested, and updated the least often. Not promised to be bug-free. |
| **Nightly** | Development builds carrying newer features and fixes than Stable | Bugs and regressions are still possible; less tested than Stable. |
| **Alpha** | Experimental builds, the earliest and the most frequent | The likeliest to be rough: incomplete features and regressions are expected. |

Switching channels at any time is possible from the Updates page, and the choice is
saved across launches and updates. **Alpha and Nightly ask for confirmation before
taking over**, because moving to them means less-tested builds, and moving between
generations of releases may require a reinstall when versions or data formats moved
apart. Switching back to Stable needs no confirmation. Your settings are preserved
when you switch; the update check just re-asks the releases of the channel you moved
to, never reusing an answer cached for the channel you left.

A channel can only ever hand out a release that was actually published: until the 3.1.0
release is published, the checker sees the previous published release and reports the
build as up to date against nothing newer. It never invents a release, and every channel
reads only this repository's Releases:
<https://github.com/codeboy2012/PwEevee/releases>

## Liquid Glass

# Installation

PwEevee distributes IPA files.

You will need a compatible iOS signing/sideloading method to install an IPA.

The exact installation process depends on your environment and signing method.

PwEevee does not require a specific sideloading application.

Before installing:

1. Verify your iOS version.
2. Verify the Spotify version associated with the IPA.
3. Make sure your signing method supports the application.
4. Remove conflicting Spotify modifications if necessary.
5. Keep a backup of anything important.

> **Do not assume that multiple Spotify modifications can safely be installed together.**

# Troubleshooting

If PwEevee does not work correctly, first verify:

### 1. Spotify version

Make sure the Spotify version matches the intended build.

### 2. iOS version

Check that your device meets the requirements of the underlying EeveeSpotify release.

### 3. Signing

Some installation failures are caused by the signing environment rather than PwEevee itself.

### 4. Conflicting tweaks

Other Spotify modifications may conflict with PwEevee.

### 5. Settings and icon previews

A grayed-out premium row is intentional — the other premium spoof is active. Turn the
active switch off to re-enable the grayed one immediately.

### 6. Developer Mode and certificate trust

On iOS 16 and newer a sideloaded build will not launch until **Developer Mode** is enabled
(Settings → Privacy & Security → Developer Mode → on → Restart → Enable) **and** the
signing certificate is trusted (Settings → General → VPN & Device Management). Free Apple
ID builds expire after 7 days. See [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).

### 7. Login or signup fails

On iOS 17 (reproduced on an iPhone SE 2nd generation, iOS 17.8.1) Spotify login and signup
currently return a **"Spotify server error."** This is a known issue of this build,
acknowledged for a future update — it is not a signing problem and re-installing does not
fix it.

## Packaging the IPA (the path that produced 3.1.0)

The packaged IPA is assembled from the pinned components in this repository — no Theos
build is needed for this step:

```bash
# merges the pinned components into a decrypted Spotify base IPA, validating as it goes
PwEvevee/build-system/unified.sh <decrypted-spotify-base.ipa> -o dist/PwEevee-3.1.0.ipa
```

`unified.sh` runs the dependency resolver (duplicates fail the build), the load-command
injector, the Mach-O/bundle/structures validators, the deterministic IPA packager and the
component guard before it writes anything.

## Rebuilding the tweak itself

The `spotifyglass.dylib` that ships in 3.1.0 was built from the migrated product source
tree with Theos (`THEOS_PACKAGE_SCHEME := rootless`), in a clean `rm -rf .theos && make`.
That tree is **not** the `Spotipw/tweak/Sources` tree tracked in this repository: the
tracked tree is the pre-migration lineage, and `unified.sh` deliberately rejects a build
from it (the component guard forbids the old site endpoint and the old `spotipw.usage`
key). Publishing the migrated tree so the shipped dylib can be rebuilt from this
repository is an open item — see the pre-publication audit in `release-candidate/`.

## Tests

```bash
perl PwEvevee/build-system/tests/build-tests.pl
perl PwEvevee/build-system/tests/deb-format-test.pl
perl PwEvevee/build-system/tests/pweevee-premium-exclusivity-tests.pl
perl PwEvevee/build-system/tests/eevee-settings-tests.pl
perl PwEvevee/build-system/tests/pweevee-rebrand-tests.pl
perl PwEvevee/build-system/tests/pweevee-deb-tests.pl
perl PwEvevee/build-system/tests/website-tests.pl
```

`embedded-artifact-test.pl` additionally proves that the dylib inside a candidate IPA is
the pinned component (`PWEEVEE_IPA=<path>`, or `dist/PwEevee-3.1.0.ipa` by default).

CI (`.github/workflows/pweevee-deb.yml`) rebuilds the deb on macOS with Theos when
`Spotipw/tweak/**` changes; the unified IPA is packaged from a pinned dylib plus the
pinned EeveeSpotify component by `unified.sh`.

The build process can change when upstream projects change. PwEevee attempts to keep
integration and packaging changes understandable and reproducible.

  server error."** Acknowledged for a future update; authentication is not working on
  iOS 17 in this build.
