## 3. Bugs found and fixed — the 7c saga in one place

The section-7c `update-stats.pl` fixture tests had been failing with a chain
of three independent causes. Evidence came from instrumenting the mock server
(loopback log), overlapping the `curl` invocation log, and a differential
repro (`_dbg` scratch, since removed):

1. **The `qx{...} . qq{...}` argument loss.** The `$run` helper built the
   child command as `qx{perl update-stats.pl } . qq{--out "..." ...}`. In
   Perl that concatenates the *captured output* of the first piece with the
   literal second piece — the child ran with **no arguments at all** (used
   the live `website/data/projects.json` defaults, among other things) while
   the unused piece appeared verbatim at the end of the captured stdout.
   Fix: one `qx` string in
   [website-tests.pl:2184](PwEvevee/build-system/tests/website-tests.pl#L2184)
   with a comment explaining why the concatenation form is forbidden here.

2. **The scripted conversation was one entry short.** The mock served exactly
   one response per connection. `PwHttp` configures `curl retry = 2`, which
   retries *transient* failures — a 5xx included. The case that received the
   scripted 500 therefore consumed a second connection for curl's retry,
   shifting every later case by one response and leaving the server empty
   before the last case ("HTTP 0" through the whole tail of the run).
   Fix: the conversation ships the 500-retry pair in order
   ([website-tests.pl:2107](PwEvevee/build-system/tests/website-tests.pl#L2107)),
   with the reason commented at the entry.

3. **A real gap in `update-stats.pl`.** With no previous data, a failed fetch
   (404, 5xx, rate limit) pushed `unavailable_entry` into the output but never
   printed *why* to the run log — only the generic summary did. Fix: warn the
   reason in the no-previous-data failure branch
   ([update-stats.pl](PwEvevee/build-system/release/update-stats.pl)).

Two more checks failed transiently during the debugging because the live
`website/data/stats.json` had been clobbered by the (then) argument-less
child and the rendered homepage was one render behind. Both were resolved the
intended way: `update-stats.pl` was re-run against real GitHub (fresh etags,
nothing fabricated) and `render-site.pl` re-rendered all 13 pages.

## 4. Deliberate test-fixture change: `trace.log` removed

preserved a diagnostic copy. That instrumentation is gone; the committed
section restores the plain teardown (`remove_tree($FIX)`) and the mock is
silent again. Everything a failing run needs is asserted by the checks
themselves.
